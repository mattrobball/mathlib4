# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

This is **mathlib4**, the community-maintained mathematics library for the Lean 4 theorem prover. It contains formalized mathematics, programming infrastructure, and tactics. The toolchain is specified in `lean-toolchain` (currently Lean 4.29.0-rc1).

## Essential Commands

```bash
# Download precompiled .olean files (ALWAYS run first, otherwise builds take hours)
lake exe cache get

# Build entire library
lake build

# Build a specific file (use module path, not file path)
lake build Mathlib.Algebra.Group.Defs

# Run all tests
lake test

# Text-based style linting
lake exe lint-style

# Regenerate import files (Mathlib.lean, etc.) after adding new .lean files
lake exe mk_all
```

If builds behave strangely, try `lake clean` or `rm -rf .lake` then `lake exe cache get` again.

## Project Structure

- **Mathlib/** — Main library organized by mathematical area (Algebra, Analysis, CategoryTheory, Topology, MeasureTheory, etc.). `Mathlib/Tactic/` contains custom tactics and linters.
- **Mathlib.lean** — Auto-generated root import file (regenerated by `lake exe mk_all`)
- **Archive/** — Standalone formalizations of specific results (e.g., olympiad problems)
- **Counterexamples/** — Formalized counterexamples
- **MathlibTest/** — Test suite for tactics and linters
- **Cache/** — Implementation of the `lake exe cache` tool
- **scripts/** — Build, linting, and CI scripts (Lean and Python)
- **docs/** — Documentation-only modules

## Key Conventions

- **`autoImplicit` is `false`** — All variables must be explicitly declared.
- **`pp.unicode.fun` is `true`** — Code uses `fun a ↦ b` notation (not `fun a => b`).
- **`Mathlib.Init` must be imported** — Enforced by linter; all Mathlib files transitively import it.
- **File length limit: 1500 lines** — Enforced by `linter.style.longFile`. Split files if they grow too large.
- **Line width: 100 columns** — Per style guide.
- **2-space indentation**, UTF-8 encoding, LF line endings, trailing whitespace trimmed.

### Proof Strategy

#### High-level structure

1. **Reduce to kernel acyclicity** via the splitting `extraction ∘ embedding = id`
2. **Show kernel acyclicity** via monomial decomposition: decompose cocycles by Laurent exponent, use acyclicity of K_T for each component, reconstruct a primitive

#### Step 1: Reduce to kernel acyclicity

Given a (p+1)-cocycle f in the algebraic complex:
- `extractionHom(f)` is a cocycle in K_∅ at degree p+1
- K_∅ is exact at degree p+1 (by `relSimplexComplex_empty_isZero_homology`), so ∃ e with δ(e) = extraction(f)
- Set f' = f - embedding(e). Then f' is a cocycle with extraction(f') = 0
- It suffices to show f' is a coboundary

#### Step 2: Construct the primitive (kernel acyclicity)

Given f' with δ(f') = 0 and extraction(f') = 0:
- For each a ≠ 0: `componentHom a f'` is a cocycle in K_{negSupport(a)}
- K_{negSupport(a)} is acyclic (negSupport nonempty since a ≠ 0, proper by `negSupport_ne_univ`), so ∃ g_a with relSimplexδ(g_a) = componentHom a f'
- For a = 0: componentHom 0 f' = 0 (since extraction(f') = 0)
- Define G(S) in the **ring** localization:
  ```
  G_ring(S) = ∑_{a ∈ F(S)} constRingElemHom S (g_a(S)) * monomialElem a S
  ```
  where F(S) is a finite index set (from finite support lemma)
- Transport: G(S) = awayRingModuleEquiv(G_ring(S))

#### Step 3: Verify δG = f'

By `monomialCoeffMod_determines_zero`, it suffices to show all monomial coefficients agree:
- `componentHom b (δG) = relSimplexδ(componentHom b G)` (by `component_comm_δ`)
- `componentHom b G` at S = `monomialCoeffMod b (G(S))` = g_b(S) (by R-linearity + orthogonality)
- So `componentHom b (δG) = relSimplexδ(g_b) = componentHom b f'` ✓
